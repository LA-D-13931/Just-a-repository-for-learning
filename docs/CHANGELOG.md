## 2026-09-19 · v0.7.99 — Windows 图标不显示 + 启动慢

| 项 | 内容 |
|---|---|
| **问题一** | Windows 安装后应用图标不显示 |
| **根因一** | `build.win.icon` 指向 `build/icon.png`，且**根本没有 `build/icon.ico`** |
| **修复一** | 新增 `desktop/tools/make-ico.py`（无 Pillow 时手写 ICO 格式）生成 7 尺寸 ICO；`nsis` 补 `installerIcon` / `uninstallerIcon` / `installerHeaderIcon` |
| **验证一** | 解出 exe 内嵌位图，尺寸 **16/24/32/48/64/96/128/256** 齐全 |
| **问题二** | 启动很慢 |
| **实测结论** | 站点资源仅 7 MB 且**无图片**；运行时完整性校验仅 **2–4 ms**；source map 未进包；devtools 未自动打开。**主因是便携版每次启动都要解压约 276 MB 到临时目录** —— 安装版从 Program Files 直接加载，明显更快 |
| **修复二** | 便携版产物名加「便携版」标记以免误用；启用 `compression: maximum` |
| **影响模块** | 构建层（electron-builder）、打包脚本 |

## 2026-09-18 · v0.7.96 — 安装包防篡改机制

| 项 | 内容 |
|---|---|
| **实现** | asar 打包 + Electron Fuses + 构建时哈希清单（Ed25519 签名）+ 运行时自校验 + 分发校验和 |
| **踩坑 1** | `electron-builder 25.1.8` **不支持 `electronFuses` 配置项** → 改用官方 `@electron/fuses` + `afterAllArtifactBuild`；且 per-arch 施加会破坏 universal 合并（CodeResources SHA 不一致），必须放在**合并之后**；改完二进制必须**重签外层封装**，否则签封失效、进程无输出即退出 |
| **踩坑 2** | 启用 `OnlyLoadAppFromAsar` 后 **`node:fs` 无法打开 `app.asar`**（报 ENOENT，而同一路径 `existsSync` 为真）→ 改用 Electron 的 `original-fs` |
| **踩坑 3** | 把 asar 整文件哈希写进**它自己的**清单是**自指**的，永不收敛 → 移除该字段 |
| **未做** | 代码签名与公证（无证书）。脚本已备在 `desktop/tools/` |
| **影响模块** | 构建层、桌面版启动链路 |

## 2026-09-18 · v0.7.97 / v0.7.98 — 安装包与图标清理

| 项 | 内容 |
|---|---|
| **问题** | 发给用户的 Windows 包启动即报「文件已被修改，缺少 manifest.json」 |
| **根因** | 封签是**手动步骤**：`seal` 之后再跑一次 `electron-builder` 会**覆盖** `win-unpacked`，清单被抹掉 |
| **修复** | 把清单**写进 `app.asar` 内部**（不再放 Resources 目录）；新增 `tools/build-all.sh` 固化正确顺序：Windows 必须「先 `--dir` 出 unpacked → 封签 → 再 `--prepackaged` 打成 exe」 |
| **图标重复** | 构建目录里留下**未打包的 `.app`**，macOS 把它们当独立应用 → 启动台/聚焦出现 4 个同名图标。修法：打包后删除中间产物；含 `.app` 的备份压成 zip 或移出工作区（工作区会被索引） |
| **影响模块** | 构建层、打包脚本、备份策略 |
