# 本站诊断陷阱

> 排查这个站点的**渲染 / 内容 / 双语文案**问题时，先读这一份。
> 这里每一条都是真实踩过的坑，共同点是：**看起来在查 A，实际查到的是 B**，
> 于是得到假阳性并据此"修复"，把好的东西改坏。
>
> 建立：2026-10-10 ｜ 起因：同一次会话里，同一类陷阱在三个不同地方各犯一次。

## 一、正则类（最容易吃亏的一类）

### 1. 交替分支必须「长在前」

```python
# ✗ 错：js 会先吃掉 package-lock.json 的前两个字符
re.findall(r'(tests/[\w\-.]+\.(?:py|js|json))', s)
#   → 匹配出根本不存在的 tests/package-lock.js

# ✓ 对：长的分支写在前面
re.findall(r'(tests/[\w\-.]+\.(?:json|py|js))', s)
```

### 2. 子串会伪装成命令

```python
# ✗ 错：\leftrightarrow 里含子串 \left，于是被算成「有 \left 没 \right」
len(re.findall(r'\\left', tex)) != len(re.findall(r'\\right', tex))
```

判 `\left`/`\right` 是否配对时，必须用**词边界**：
`re.findall(r'\\left(?![a-zA-Z])', tex)`。

### 3. `$...$` 交替定界符不能跨段正则匹配

```python
# ✗ 错：\$([^$]+)\$ 在「$A$ 中文 $B$」上会先匹配 $A$，再匹配「$ 中文 $」
#        于是把中文判成「在数学里」
re.findall(r'\$([^$\n]+)\$', s)
```

正确做法是**按 `$` 切分后取奇数下标**（第 1、3、5… 段才是数学）：

```python
parts = body.split('$')
spans = parts[1::2]          # 交替取，奇数下标即数学内容
```

### 4. 别用「字符数上限」当判据

真实事故：判据写成 `/\$[^$]{1,200}\$/`，**超过 200 字符的行间公式一律被判成
「没有公式」**，于是永不排版。短公式全好、只有长公式坏，而且源码看起来完全正常。
`[^$]` 不含 `$`，本就没有回溯风险，**上限要大到不会误伤**（现为 4000）。

## 二、MathJax 类

### 5. 「不报错」不等于「渲染正确」

| 写法 | 实际结果 |
|---|---|
| `\boldsymbol{\alpha}` | 硬报错（懒加载缺失的扩展） |
| `\bm{\alpha}` | **不报错**，但把 `\bm` 当**字面文字**渲染出来 —— 比硬报错更隐蔽 |
| `\mathbf{\alpha}` | 不报错，对希腊字母**毫无加粗效果**（字形与 `\alpha` 逐位相同） |
| `\vec{\alpha}` | ✓ 正常（本站向量记号，全站已用 1970 次） |

**这份构建里「加粗希腊字母」没有任何可用写法** —— 因为 `tex-svg.js` 是
**单文件自包含**的，没有 `input/tex/extensions/` 目录，任何触发懒加载的命令都会失败。

判断某个命令到底行不行，**必须逐条单独开页测**：一条失败会中断整批，
混在一起测会得出错误的结论。`tests/check-mathjax.py` 守住了已知的禁用命令。

### 6. 长公式的「挤成一团」是定位内容损坏的钥匙

内容损坏的一种形态是**两个数学片段被挤在一起**：`$\varepsilon\varepsilon$`、
`$|x|\dfrac{f(x_0+h)-f(x_0)}{h}$`、`$\dfrac{0}{0}(-1,1)$`、`$n(t)h \to 0$`。

**它不是"公式写错了"，而是有人把一整段文字从中间摘走了** ——
被摘走的那段会在别处被 `$$…$$` 包着（因为定界符留在了原地）。

所以定位方法变成确定的：
1. 那个「挤压点」= 文字应当插回的**位置**；
2. 别处被 `$$` 包住的中文散文 = **被摘走的内容**；
3. 把内容放回挤压点、把被压掉的那个 `$` 还回原位 —— **语序自动复原，不需要新增任何字**。

实测 9 处全部如此还原通过，没有一处需要补字。

## 三、页面结构类

### 7. 判断题的选项顺序**不固定**

全站 **118 题**是「正/错」顺序，**22 题**是「错/正」顺序。
按「第 1 项 = 正确」硬编码，会把这 22 题全部误判。**按选项文本匹配**。

### 8. 公式可能藏在子元素里

```html
<li><span class="opt-body">$\dfrac{\pi^{2}}{6}$</span></li>
```

`li` 没有直接文本子节点，只看直接子文本的判据会判它「没有公式」；
而父子去重又会把 `.opt-body` 丢掉 —— **两条路都漏，永久不排**。
判「还有没有未排公式」必须**看整棵子树**。

（已排好的部分 MathJax 会把 `$…$` 原文取走，所以用 `textContent` 判断不会重复入队。）

### 9. 两个排版循环会互相打架

`anchor-fix.js` 只在**带锚点**时启动自己的 flush 循环。所以同一页：
无锚点快滚 = 0 处未渲染；**有锚点快滚 = 49 处未渲染、容器少 72 个**。
对照实验时，**唯一变量是 URL 里的 `#`**。

### 10. 闭合的 `<details>` 内容不在视口

`IntersectionObserver` 永不触发，公式不会被排。本站用 `toggle` 监听在展开时补排。

## 四、诊断方法论（比上面任何一条都重要）

1. **先建可红可绿的回路，再猜原因。** 一个能在**这个** bug 上变红、修好后变绿的
   命令，胜过任何推理。本页多数坑都是"没有回路就动手"造成的。
2. **写完检测器，先拿已知好样本校准。** 上面第 1、2、3 条都是检测器自身误报，
   如果先拿一个已知正常的页面跑一遍，立刻就能发现。
3. **假阳性必须先排除，再动手改。** 本轮首轮扫描报 28 处，其中 **21 处是检测器
   自己的假阳性**；直接开修会把 21 处好内容改坏。
4. **改动前后要能对照。** 怀疑某个改动破坏了页面时，用
   `git checkout <sha> -- <file>` 回到旧版跑同一个测量，**数字说话**。
   本轮两次靠这个抓回自己的错误改动。
5. **拿不准就停手问人。** 尤其：早于 git 历史的档案、只此一份的产物、
   「看起来像垃圾但文档说不能删」的东西。
